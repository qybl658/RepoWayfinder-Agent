# 本地验证任务复现材料

这里保存受测的固定业务任务、合成输入和独立验收程序。完整结果与口径见 [比较报告](../../docs/LOCAL_VERIFICATION_COMPARISON.md)。验收通过只证明程序覆盖的断言，还需检查交付说明、任务范围和进程清理。

## 保持生成与验收独立

1. 原生组、产品组分别使用新的随机任务目录和客户端环境，保持相同模型、思考设置、原生工具与审批模式。产品组只增加正常分发的 MCP 和随附说明，不增加隐藏测试提示。CSV a3 是产品先运行；服务 a4 是原生先运行。
2. 测试控制目录、验收程序和另一组产物不能放在任务目录或其可探索的相邻目录。产品运行目录也不要带上本目录中的验收程序。目录分离不是操作系统沙箱；按宿主的正式机制约束业务访问，并保存实际读取记录。
3. CSV 只将 `csv-input.csv` 复制为任务目录的 `input.csv`，发送 `csv-task.txt`。服务 a3 使用 `service-task.txt`，隔离服务 a4 使用 `service-task-isolated.txt`；同一配对两组发送相同字节的提示。不要用后续修改覆盖原受测提示，也不要将验收程序复制到模型任务目录。
4. 等生成模型退出后，从独立控制目录运行验收。`TASK_DIRECTORY` 是本次交付目录，`CONTROL_SCRATCH` 和 `RESULT_JSON` 位于独立控制区，不能指向另一组产物。使用已有 Python，不安装依赖：

```text
python verify_csv.py "<TASK_DIRECTORY>" --scratch "<CONTROL_SCRATCH>" --output "<RESULT_JSON>"
python verify_service.py "<TASK_DIRECTORY>" --scratch "<CONTROL_SCRATCH>" --output "<RESULT_JSON>"
```

5. 逐组核对真实读写、动态执行代码及子代理记录，检查是否读过验收器或另一组答案。缺失关键记录时保留不确定性，不能仅凭没有匹配到路径就判定通过。另检查任务拥有的服务是否停止，以及 README 是否符合真实行为。

保存每次运行的源码版本、完整任务文本、客户端版本、模型设置、输入/输出/缓存用量及运行时段；记录阻断和失败的成本。先固定判断标准，再做比较，不挑选最快或成功重试。保留原始证据在受控本地目录，公开时只发布脱敏摘要。

此处不提供或复制登录配置、认证引用、私人规则、机器专用运行器或原始会话日志。
