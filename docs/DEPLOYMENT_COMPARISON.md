# Grok 三方向任务对照

2026-09-27，Grok 4.7 / high 完成三个固定源码任务：两个轻量部署项目，以及带登录、权限和数据库持久化的 Flaskr。每个任务各跑一组原生工具与一组原生工具 + RepoWayfinder，六次全部完成，不设模型轮数或进程时间上限。

每组仅一个样本，固定工具组先跑；缓存与顺序影响未控制。token 合计包含缓存读取，不等于费用节省。时间覆盖模型运行器启动至退出，独立验收、开发及主控时间另计。Flaskr 的 token 未减少，不能据此宣传复杂任务普遍增效。

## 方法与任务

Grok CLI 1.0.41；同一台 Windows 主机、相同模型与 high 强度、同样的原生工具和权限模式。工具组额外提供 RepoWayfinder MCP；实际每组调用一次 `rw_run`，原生组没有实际 MCP 调用。Python 任务使用 3.11.9，Node 任务使用 22.23.1；项目依赖本地安装。基线环境包快照前后相同，此检查不证明所有写入都受目录隔离。

- Bottle 报价 API：[任务提示](../benchmarks/tasks/bottle_quote_zh.txt)，[bottlepy/bottle@b0a0a10](https://github.com/bottlepy/bottle/tree/b0a0a1014f7a7e6f6b7c193886a0913f46ee3ee6)。
- http-server 静态站点：[任务提示](../benchmarks/tasks/http_server_static_zh.txt)，[http-party/http-server@af0ac3e](https://github.com/http-party/http-server/tree/af0ac3e4b9bd5fff55337aee32bf37f6116c7b4f)。
- Flaskr 登录与持久化：[任务提示](../benchmarks/tasks/flaskr_state_zh.txt)，[pallets/flask@2c1b30d](https://github.com/pallets/flask/tree/2c1b30d0503cfb064f1cb252e6614a06915a362a)。

独立验收使用真实 HTTP：Bottle 覆盖价格计算、输入错误和重启；http-server 覆盖页面、样式、CSV 下载、404 和重启；Flaskr 覆盖注册登录、发布修改、越权拒绝、退出及数据库重启后保留。六组均保留原始尝试，没有用重跑中的最优结果替换。部分辅助脚本曾写入宿主临时目录，这项普通位置偏差已获用户接受；不宣称完整文件系统隔离。

## 验收脚本问题与处理

首次 Bottle 工具组验收在 27 项断言全通过后，清理临时日志时遇到 Windows 子进程占用；首次 Flaskr 工具组在 30 项断言全通过后，清理临时 SQLite 时遇到验收器自身连接未关闭。保留了初次失败证据，分别修正精确进程树清理与显式关闭只读连接，再对同一交付验收通过。断言未改，模型未重跑；修复仅涉及验收脚本。原始失败及补丁保存在本地问题包。

## 对后续修改的判断

两个轻量任务出现不同程度的时间与 token 减少；Flaskr 只小幅缩短时间，token 略增。这个单样本尚不足以定位原因，更不能证明增加工具就会减少复杂任务推理开销。本次保持已有产品核心，保留这项收益边界供后续模型分析；若优化，应针对明确瓶颈并保护已通过的任务行为。
