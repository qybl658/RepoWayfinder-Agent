## 旧/新持久规则配对

两组均 Grok CLI 1.0.41、Grok 4.7/high、同一冻结实现和 Bottle 任务、相同标准 guide、native/MCP/权限配置。只改变家目录持久规则；旧规则仅临时切回一次，随后立即恢复。未限制轮数或总运行时间。

新组 wall 增加 33.42%，usage 合计增加 50.44%。cache 是跨轮累计读取，合计不是新增 token、消费金额或订阅配额。API 时间不能拆成推理、网络与排队；局部工具请求→结果收行区间合计为 49.424→78.093 秒，含 CLI 缓冲/编排等，不能称工具纯执行时间。

新组第一处分歧是原生命令未设置返回 checkout 的 cwd，git 与相对 venv 命令失败，下轮才改目录。之后验证脚本把 Windows taskkill 本地编码输出当 UTF-8，解码失败并修复重跑。扩展指导中的 cwd 约束藏在协作长段落，未被执行；源码读取只从 8 增为 9 次，不能把这次差异主要归为重复读源码。保留失败和恢复成本，没有只报通过结果。

只有一组固定顺序配对；共享依赖/网络缓存、服务端条件未控制。不能宣称新规则必然致慢，也不能宣称某条规则可节省特定比例。宿主原有个性化规则未公开，外部无法逐字完全复现。冻结提交只是本地来源身份，并非公开仓库 ref。

## 普通入口质量与加载

CSV 案例直接从普通 Grok CLI 新任务启动，没有 benchmark guide、任务工具过滤、web 禁用或权限覆盖。wall 564.938 秒、API 558.175 秒，11 轮/14 工具，input109830/output40729/cache424832（creation0），合计575391。15 项独立检查覆盖行守恒、重复/冲突/非法输入、中文、金额、重跑不追加及 BOM 输入，全部通过。这是可迁移质量证据，缺少旧规则同任务对照，不能证明日常速度提升。

普通 CLI 保留原生读写/命令以及原有 web、media、workflow、MCP 能力目录。仅证明这些能力没有被本轮屏蔽，未逐一执行所有能力。MCP 初始化完成标记在启动后 2.168 秒；没有识别到连接失败或可归因的多余等待。日志有遥测发送失败警告，不能据此认定 MCP 慢或关闭工具。

显式命令/路径审计：Bottle 两组均在系统 Temp 创建烟测辅助文件，新组还把绑定验证 stdout/stderr 写到 Temp；普通 CSV 也把验证脚本和 BOM 小样写进 Temp，随后清理。交付业务通过不等于全部目录范围合规。Bottle 指定 inputs/deliverables 在 bench-delivery、没有所有写入句子，辅助 Temp 文件属于解释性偏离；普通 CSV 也没有所有写入句子，交付路径符合，辅助 Temp 写入如实单列，不判成不存在的禁写要求。常规 CLI/git/pip cache 另算；未在本次命令审计中发现凭据/全局安装写入，此审计不是全文件系统证明。

## 实际日常配置与修复

现有唯一 owner `~/.grok/rules/working-agreements.md` 按最新要求改为质量优先、总 token 优先于时间，尽量同时明显降低两者。总 token 包括主模型、子模型、交接和返工，不能把消耗转给子模型就算节省；不改主模型/思考、权限和完整验收。

| 持久规则版本 | bytes | CLI 近似 tokens |
|---|---:|---:|
| 原规则 | 13724 | 3431 |
| 受测扩展版 | 15205 | 3801 |
| 前一最终版 | 14589 | 3647 |
| 当前 token 优先版 | 13411 | 3352 |

只在协议迁移时需要的说明和旧运行时名称对照移到 rules 外的按需 reference，知识完整保留；实际 Grok 工具和触发说明未改。普通工作入口和新任务 `grok inspect --json` 均显示 global 自动加载当前13411字节/约3352tokens，迁移 reference 不在加载列表。较前一最终版少1178bytes/295近似tokens（约8.1%），较原规则少313bytes/79近似tokens（约2.3%）。这是常驻上下文的结构减少，不能外推整任务大幅省 token 或省时；最终版本与受测新版本不同，未另跑模型验证。

保留用户当前模型/思考，不让旧型号条款自动改主模型；短命令直接等待，真正长期或有并行价值的任务才后台事件等待。将每次终端显式 checkout cwd、返回的 Python executable、任务辅助文件位置、Windows 系统输出 bytes 放在现有运行时表。HTTP 服务用单次超时的真实 HTTP 请求核对就绪/业务/重启，停服核对本任务拥有 PID；Test-NetConnection 保留给网络诊断。后者有独立本地服务状态判别支持，但不是整任务性能承诺。仍保留必要调查、完整质量和错误/恢复验收，未改账号、模型配置、登录、工具审批或全局 trust。

专项 repository profile 未采用、未发布，新增选项/过滤/工作流禁用分支和专项文档已经撤掉。实验的冻结历史保留在本地。

Driver 原先 PIPE 收行并无界 join：父 CLI 已退出，后台子进程继承 stdout 会继续阻塞。小 fake 中旧版等待子进程1.234秒，修复后父返回约0.063秒，后台子仍正常输出，raw完整保留。现在 stdout 直接落文件，旁路观察以50ms采样，CLI退出后只读取当时有限范围；晚到的子进程输出保留raw，不延长计时。未知JSON形状不会中断采集。6项聚焦检查通过，中断只终止并等待本次CLI、不杀后台进程树。实际三次实验最后result收行至runner返回分别为0.734/2.703/1.860秒；冻结版没有独立记录父退出时刻，不能据此追补精确退出时间。

## 回滚与公开边界

原/受测/最终规则完整字节只保留本地私有证据。恢复前需确认 owner 没有后续外部编辑，否则保留后续修改。driver可回到本轮前版本；当前修复不改CLI后台进程所有权。现有协议allowlist快照再次刷新（100项）；它不包括Grok rules或迁移 reference，未扩展为账号config迁移，也未导出凭据、私人规则全文或raw traces。

结构加载与实际速度收益分别报告。日常通用性能改善仍未证；可支持的改动是更靠近触发位置的故障提示和driver生命周期修复。
