# 国内模型静态部署试验收尾

本轮未形成可用的工具性能对照。四次实际模型尝试及未启动的准备记录全部保留，没有切换到付费调用。

| 尝试 | 会话可观察 tokens | wall(s) | 回合/工具 | 结果 |
|---|---:|---:|---:|---|
| qwen-static-formal-p1/native | 455,992 | 630.125 | 9/18 | 原生执行/写工具缺失，环境前提失败 |
| qwen-static-formal-p2/native | 1,006,446 | 507.422 | 26/37 | 免费额度 guard 停止，独立验收23/25 |
| glm-static-formal-p2/native | 898,989 | 2621.890 | 37/36 | 交付结构不完整，标准25项未进入 |
| glm-static-formal-p2/product | 2,275,379 | 2920.469 | 70/69 | 交付结构不完整，标准25项未进入 |

四次会话累计可观察 token **4,636,806**，CLI 运行共 **6679.906 秒**。input 已含 cache；不能再次加 cache，也不能当作账单或免费额度扣减。此数不包含主控、代理开发排查的 token 或独立验收耗时，不代表本项目全部成本。

Qwen 的第一次失败由 CLI text headless auto 路由预先排除写入/执行工具造成；官方 stream-json 路由恢复了完整注册及真实无模型写/读/命令链，保留 auto 安全审批。第二次做到23项，但免费额度用完即停；未启动产品组，现场和官方 session 恢复点留在私有目录。

GLM 原生与产品均把 serve.cjs 放在仓库根而非合同指定 bench-delivery；因此标准验收未进入，不能写为25项业务全部失败。产品连接并发现10个 MCP 工具，实际调用0次，所以较多 tokens/回合不能解释为工具执行收益或工具流程性能。

范围核对：已观察的业务读写都在各自任务内，未发现 oracle/另臂读取；客户端自身后台输出是运行时例外。两组 GLM 以及 Qwen 第二次自有后台进程匹配均为0，未额外 kill，产物/会话原样保留。范围是日志审计，不是 OS sandbox 或完整系统写监控。

宿主等待单列：GLM native 19次 host ask，request→decision 文件就绪累计640.220s，3次已因默认60s callback 超时取消；GLM product 36次累计1691.391s，无 callback 超时，窗口600s。此累计含 native 超时后才到达的决定，不等于实际 blocked duration，不从 wall 中机械扣除。产品最长378.052s（UTC12:44:44.097673→12:51:02.149412）因本代理上下文压缩/恢复期间审批迟到；另有152.793/150.135s迟到。它们是宿主协作等待，不能归为 API/模型慢。API 字段也不等于纯思考。

未调用模型的准备：qwen-static-p1、glm-static-formal-p1；两次 Qwen 产品臂均未启动。无模型 catalog/native链及 SDK 控制模拟不计模型尝试。

当前结论：本轮不支持国内模型工具降本增效结论，也不证明模型普遍不可用。原始日志、私人路径、session及认证资料不进入公开记录。

受测源码固定为 `b893808883e56e18d317ede3a1bb17519b2bdda9`，客户端为 Qwen Code 0.24.7。安装版本源码存在接收并传递 MCP 服务说明的路径，但未捕获实际 API 请求，因此未采用工具的原因仍未确定。
