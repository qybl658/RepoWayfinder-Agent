### 执行与验收口径

两组起始模型、思考档位、原生工具参数、过程级 `--always-approve` 和 `PIP_REQUIRE_VIRTUALENV=1` 相同，不加新沙箱配置。工具组增加 RepoWayfinder MCP，承担固定源码与版本化环境；文档编写、构建和检查由原生工具完成。原生组配置无 MCP 并显式拒绝 `MCPTool(*)`，实际原段和续接都没有 MCP 或其他模型调用。CLI init 公布的是工具目录快照，不能据此推断 MCP 已连接或有调用权限；以配置检查和实际调用为准。

预跑和正式工具组曾将临时辅助脚本写入系统 Temp，运行后自行删除。审计保留这个原范围偏差；用户明确优先比较 token 与交付结果，接受这类临时脚本位置偏差，未为此新增模型重跑。两次构建、源码安装、FAQ 修改、清理和 ZIP 均有实际证据，未观察到直接篡改生成 HTML/搜索索引或全局 pip 安装。三套基础 Python 的包清单在各阶段前后相同；这不是完整操作系统写入审计。

这是单任务、单组正式样本，运行顺序和共享机器缓存仍有影响。它证明本次交付下记录到的差值，不证明跨项目稳定收益，也不用于 Grok 与 DSH 的模型排名。

### 改了什么

1. `rw_run` 接受短命令数组；不用模型重复编写 action/type/purpose/reason。旧版仅规划一轮就消耗 6,596 输出 token，新版对应一轮为 2,727；这只是观察到的相关变化，不能把全部差值归因于接口。
2. MCP 只返回一份 JSON 文本，去掉重复的 text + structuredContent。工具发现改成精确搜索 `rw_run`，避免模糊排序先返回 cancel。
3. 一次最多等待 50 秒，完成即返回。短任务不必新增查询轮次。
4. 有限命令入口不再因为脚本名含 `main.py` 等字样就把它当服务器。用真实子进程、真实临时 Git 仓库验证了写出 JSON 文件的完整路径。
5. 支持 Git 元数据读取，保留原校验，并拒绝写操作、输出重定向和外部差异工具选项。

新版仍是工具发现 + 一次 `rw_run`，无失败重试。实际计划执行为 21.453 秒，CLI 报告 API 时间 48.961 秒。没有降低模型或 reasoning effort，也没有减少文件验收要求。源码、安装日志和完整产物仍留在本地。

## 首轮失败也计入记录

初始工具版用时 337.047 秒、20 轮、29 次工具调用，未在轮数限制内完成。报告用量：未缓存输入 128,991，缓存读取 536,064，输出 22,781，合计 687,836 token；CLI 报告 costUSD 0.225318。

原因和修复：

1. 旧核心拒绝 `gitingest` CLI 前缀。新增从 pyproject 静态脚本声明到作业虚拟环境可执行文件的适配；缺失时明确失败，不调用全局同名命令。
2. 计划拒绝后没保存源码路径，改计划只能重新获取。现在先保存源码身份，支持同作业 replan，保留原证据。
3. Windows 默认编码使一次 CLI 输出遗漏读取失败的源码。结果断言拒绝了这次假成功；目标子进程现在使用 UTF-8，不改系统编码。
4. 修正准备期间取消的状态窗口，取消后不进入自动执行。

原生组首次被测试配置 `dontAsk` 拦截 PowerShell 复合命令，未开始任务；不能作为能力失败。该次用了 2 轮，未缓存输入 11,659、缓存读取 13,952、输出 3,984，CLI costUSD 0.01842732。后续命令参数纠正的一次启动在模型调用前退出，用量未知/未报告。有效原生运行使用 Grok 支持的进程级 `--always-approve`；未改全局权限。最终工具组通过 `grok_task.py` 的 `dontAsk` 和本服务许可运行。

这些探索成本不能藏进修好后的一行“省 token”。有效组对照展示的是修复后一次任务的边际表现，不是本次研发净节约。
