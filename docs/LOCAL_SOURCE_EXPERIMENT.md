# 本地来源与其他 Agent 的复用边界

2026-09-30：本地合成 Git 仓库的有限原型通过了 10 项检查。正式 `rw_run` / `rw_prepare` 接口仍只接受 GitHub 仓库；本实验没有新增通用本地路径或任意 URL 接口。

## 实际做了什么

[可运行原型](../examples/local_source_probe.py) 建立一个无网络、无凭据的合成 Git 仓库，仅替换源码获取适配器，使用真实的计划检查、项目 Python 环境、命令执行、输出检查和 `rw_replan` 恢复代码。调度改为串行、进程内执行，因而这不是 MCP 或异步 worker 的接入验收。

初次数据处理故意因负数参数失败。随后只修改任务输入，在同一 job、checkout 和 Python 环境重新执行，独立读回结果 `total=20`。只获取一次源码，两次执行证据均保留，原仓库保持干净且没有生成环境或结果文件。全程没有模型调用。

清理后的公开核心 `f2288ea` 已运行该原型。[检查结果](../benchmarks/results/2026-09-30-local-source-prototype.json)。运行条件是已安装本项目依赖、Git 和 Python 3.11；输出目录必须尚不存在：

```powershell
.\.venv\Scripts\python.exe examples/local_source_probe.py --candidate . --output D:\rw-local-probe
```

输出保留在指定目录，可查看 `result.json`、`worker.log` 和 `jobs-state/jobs`。原型只处理自己创建的合成仓库，不接受用户已有仓库。这避免把“已提交的源码”与用户尚未提交的修改混为一谈。

## 可以迁移的部分

批量执行、完整日志留本地、紧凑状态、复用环境以及失败后只重做受影响步骤，不依赖 GitHub 的搜索 API。本实验验证了这些执行和恢复能力可以用于一次有限的数据处理任务；它没有测量 token 或时间收益。

生产级本地来源还需明确允许读取的根目录、dirty/untracked 文件选择、快照一致性、符号链接及恢复身份。其他 Git 服务还涉及 URL、凭据与网络边界。当前证据不足以把任意来源入口直接开放，所以本轮保留原型和明确的接口边界。

已部署的 Agent 若能调用本地 MCP，可以作为普通调用方复用这些工具，使用自己的任务 workspace 和审批规则。环境准备后可用原生工具继续写作或处理文件。执行层本身不调用模型，不把“让另一个 Agent 再优化一次”作为隐含步骤。本轮没有部署嵌套 Agent，也不声称已验证递归调用的成本或权限隔离；这样的大框架目前没有足够收益证据。
